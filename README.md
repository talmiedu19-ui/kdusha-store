# חנות יודאיקה - מדריך שלב אחר שלב

פרויקט Next.js 14 בעברית (RTL) עם קטלוג, עגלה, צ'קאאוט ושמירת הזמנות.
המוצרים בקובץ `data/products.js` הם **דוגמאות בלבד** - יש להחליף אותם במוצרים שלך.

---

## שלב 1: התקנת כלים (פעם אחת)

1. **Node.js** גרסת LTS מ-https://nodejs.org (בדיקה: `node -v` בטרמינל).
2. **VS Code** מ-https://code.visualstudio.com
3. (מומלץ) **Git** מ-https://git-scm.com

## שלב 2: פתיחת הפרויקט

1. חלץ את קובץ ה-ZIP לתיקייה, למשל `C:\projects\kdusha-store`.
2. פתח את התיקייה ב-VS Code.
3. פתח טרמינל (Ctrl+`) והרץ:

```bash
npm install
npm run dev
```

4. פתח בדפדפן http://localhost:3000 - האתר אמור לעלות. כל שינוי בקוד מתעדכן אוטומטית.

## שלב 4: הוספת מוצרים אמיתיים

1. ב-AliExpress בחר מוצר, ובדוק במוצר:
   - **איכות ודירוג המוכר**, זמן משלוח לישראל, תמונות ותיאור.
   - **מזוזות:** באליאקספרס נמכרים לרוב קלפים מודפסים שאינם כשרים. מומלץ למכור רק **בתים (נרתיקים)** ולציין במפורש "הקלף נרכש בנפרד מסופר סת״ם".
2. הוסף אובייקט חדש למערך `allProducts` בקובץ `data/products.js` (מוצר עם `published: false` מוסתר מהאתר, שימושי לטיוטות). בשדה `supplierUrl` שמור את הלינק לספק (לשימושך בלבד).
3. **תמונות:** שים קבצים בתיקייה `public/images/` (צור אותה) וכתוב `image: "/images/kippa1.jpg"`. אל תעתיק תמונות של מוכרים בלי רשות - צלם דוגמאות בעצמך (כשיש לך מוצר ביד) או בקש רשות מהמוכר.
4. קבע מחיר מכירה: עלות מוצר + משלוח + מיסוי יבוא + עמלת סליקה + רווח.

## שלב 6: דפים משפטיים (חובה לפני מכירה)

הוסף דפים (בתיקיות `app/terms`, `app/privacy`, `app/returns`, `app/contact`):
- **תקנון ותנאי שימוש**, **מדיניות פרטיות**, **מדיניות ביטולים והחזרות** לפי חוק הגנת הצרכן.
- פרטי העסק: שם, מספר עוסק, טלפון ואימייל, כתובת.
- ציון זמני אספקה אמיתיים (משלוח מחו״ל לרוב 2-4 שבועות).
- ציון מחירים כולל מע״מ אם חל עליך, ושקיפות לגבי מיסוי יבוא.

מומלץ לבדוק את הניסוח מול איש מקצוע. כעוסק זעיר, בדוק גם את תקרת המחזור השנתית המותרת ואת חובות הדיווח ברשות המסים - אם המחזור צפוי לעבור אותה תצטרך לעבור לעוסק מורשה.

## שלב 7: חיבור תשלום

הקוד מוכן לחיבור: ב-`app/api/checkout/route.js` יש `paymentUrl = null`.
צריך ליצור חשבון אצל חברת סליקה ישראלית, למשל **PayPlus**, **Grow (משולם)**, **Cardcom** או **Tranzila**, ולקרוא בתיעוד שלהם ל-API של "יצירת דף תשלום" (Payment Page / Payment Link).

התהליך:
1. ב-`route.js` קוראים ל-API של חברת הסליקה עם הסכום, מספר ההזמנה ופרטי הלקוח, ומקבלים כתובת דף תשלום.
2. מחזירים אותה ב-`paymentUrl` - הדפדפן יעבור אליה אוטומטית.
3. מגדירים **Webhook / callback** שהחברה קוראת אליו אחרי תשלום, יוצרים route חדש (למשל `app/api/payment-callback/route.js`) ומעדכנים את סטטוס ההזמנה ל-`paid`.
4. מפתחות API שומרים ב-`.env.local` (לעולם לא בקוד ולא ב-git), ונקראים בקוד דרך `process.env.NAME`.

**קבלות:** רוב חברות הסליקה מפיקות קבלה/חשבונית אוטומטית ללקוח אם מפעילים זאת בהגדרות, וכך לא תצטרך להוציא ידנית. בדוק מול החברה שהיא תומכת בעוסק זעיר.

## שלב 8: הזמנות וספק

כרגע ההזמנות נשמרות בקובץ `orders.json` בזמן פיתוח. בפריסה אמיתית יש להשתמש במסד נתונים (למשל Supabase או Vercel Postgres), כי בפריסה לשרת ללא דיסק קבוע הקובץ יימחק.
אחרי תשלום מוצלח: אתה מזמין את המוצר מהספק ומכניס את כתובת הלקוח, ושולח ללקוח מספר מעקב.
בהמשך אפשר להוסיף שליחת אימייל אישור (Resend / Nodemailer) ודף ניהול הזמנות.

## נגישות (חשוב לגבי חשיפה לתביעות)

האתר כולל: תפריט נגישות (כפתור ♿ בפינה), דף `/accessibility` (הצהרת נגישות), קישור "דלג לתוכן", חיווי מיקוד, תוויות לשדות טפסים, ניגודיות צבעים מותאמת ותמיכה ב-`prefers-reduced-motion`.

**מה שחייבים לדעת:**
- תפריט נגישות לבדו **לא מגן** מתביעה. מה שקובע הוא נגישות האתר עצמו (תקן ת״י 5568, המבוסס על WCAG 2.0 ברמה AA) ופרסום הצהרת נגישות נכונה ומלאה.
- בדף `app/accessibility/page.js` יש להשלים את הפרטים שבסוגריים [ ] (שם רכז נגישות, טלפון, אימייל, תאריך). אל תכתוב בהצהרה דבר שלא נבדק בפועל.
- בכל מוצר חדש מלא טקסט חלופי לתמונה (בקוד זה `alt` שנלקח משם המוצר) והקפד שהתמונות לא מכילות טקסט חיוני.
- לפני הפרסום: בדוק את האתר בעצמך עם מקלדת בלבד (Tab, Enter), עם קורא מסך (NVDA בחינם ל-Windows), ועם כלי כמו Lighthouse ב-Chrome או axe DevTools. מומלץ גם ייעוץ של מומחה נגישות מוסמך.
- בדוק מול ייעוץ משפטי אילו חובות חלות על עסק בסדר גודל שלך, כולל פטורים אפשריים בעסקים קטנים.

## תצוגה ב-GitHub Pages (אוטומטית בכל push)

הקובץ `.github/workflows/pages.yml` בונה את האתר כאתר סטטי ומפרסם אותו בכל `git push` ל-`main`.
- הפעלה חד-פעמית: בריפוזיטורי ב-GitHub היכנס ל-Settings ואז Pages, וב-Source בחר **GitHub Actions**.
- הכתובת: `https://<שם-משתמש>.github.io/<שם-הריפו>/`. ההתקדמות נראית בלשונית Actions.
- זו גרסת תצוגה: אין שרת, ולכן הצ'קאאוט במצב הדגמה (אין שליחת הזמנה ואין חיוב). ל-Pages בחשבון חינמי הריפוזיטורי חייב להיות ציבורי.
- לא לשמור קישורי ספק (`supplierUrl`) בקוד של ריפוזיטורי ציבורי. הם נחשפים גם בקבצי האתר עצמו.
- כשתתחבר סליקה והזמנות אמיתיות, יש לפרוס עם שרת (Netlify או Vercel), כי שם `app/api` ממשיך לפעול.

## שלב 9: פריסה לאינטרנט
